## Style/pattern conventions established this session (follow these, don't reinvent)

- Ledger-over-raw-value: never edit a running total directly — insert a signed delta row, recompute from SUM. Used for `payments` and `stock_movements`.
- Public/customer-facing pages: no login, unguessable per-order or per-customer token, own exemption block in `functions/_middleware.js`.
- Every D1 schema change is a guarded `try { ALTER TABLE ... } catch {}` inline in the function file that needs it — no separate migration system.
- `logOrderEvent(db, orderId, type, label)` — call this on any new order-affecting action so it shows up in the Activity Timeline; `logViewOnce` for one-time "viewed X" events.
